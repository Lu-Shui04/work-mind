# 前端研发规范

**文件编号**：TECH-2026-011　**发布部门**：技术研发部　**生效日期**：2026-03-01　**版本**：2026-09
**适用范围**：前端研发部全体成员

## 一、技术栈约定

1. 新项目默认技术栈：**Vue 3 + Vite + Pinia + Vue Router + Element Plus**，语言统一 TypeScript 或 JavaScript（项目内不得混用）。
2. Node.js 版本统一使用 **20 LTS**，通过 .nvmrc 固定；包管理器统一使用 pnpm。
3. 引入新的第三方库须在技术评审会上说明理由、体积影响与替代方案，禁止使用已停止维护的库。

## 二、目录与命名规范

1. 页面级组件放在 views/，可复用组件放在 components/，按业务域分子目录。
2. 组件文件使用 PascalCase（如 ToolCallCard.vue），工具函数使用 camelCase，常量使用 UPPER_SNAKE_CASE。
3. 统一使用组合式 API 与 script setup 写法，禁止在同一个项目里混用 Options API。
4. 全局状态只放在 store 中，组件内不得直接修改其他模块的 store 状态。

## 三、代码质量

1. 提交前必须通过 ESLint 与 Prettier 检查，CI 未通过的分支不允许合并。
2. 禁止提交 console.log 调试代码，禁止提交被注释掉的大段废弃代码。
3. 所有对外请求必须有错误处理与超时设置，禁止静默 catch。
4. 关键工具函数（金额计算、权限判断、时间处理）必须有单元测试，覆盖率不低于 70%。

## 四、分支与提交

1. 分支模型：main（生产）、develop（集成）、feature/xxx、hotfix/xxx。
2. 提交信息格式：类型(范围): 描述，类型包括 feat / fix / docs / refactor / perf / test / chore。
3. 每个 PR 至少 1 名同事 review，涉及公共组件或构建配置的需 2 人 review。

## 五、性能与体验

1. 首屏加载时间（4G 网络）不超过 3 秒，路由采用懒加载，非首屏资源按需引入。
2. 单个 JS chunk 超过 500 KB 必须拆分（第三方库用 manualChunks 拆包）。
3. 长列表超过 200 条须使用虚拟滚动；表格分页每页不超过 50 条。
4. 所有图片资源须压缩并指定宽高，避免布局抖动。

## 六、发布与回滚

1. 发布窗口为**每周三 14:00 - 17:00**，其他时间原则上不发布；紧急修复走 hotfix 流程，需技术负责人批准。
2. 上线前须在发布单登记：变更内容、影响范围、验证方式、回滚方案。回滚方案必须写明具体命令或操作步骤。
3. 发布后 30 分钟内观察错误率与接口耗时，异常立即回滚。
4. 严禁在周五下午或节假日前发布非紧急变更。

## 七、接口联调

1. 前后端接口以 OpenAPI 文档为准，字段变更须提前 1 个工作日同步。
2. 分页统一使用 page/pageSize 参数，返回 total 字段。
3. 错误响应统一包含 code 与 message 字段，前端据此展示提示，不得直接展示后端堆栈。
